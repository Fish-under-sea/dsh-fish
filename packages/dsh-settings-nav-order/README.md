# @fish-under-sea/dsh-settings-nav-order

把 DSH 设置面板左边那列菜单（通用设置 / 模型 / 内置插件 / Agent 预设 / 已归档会话 / Git 同步 / …）**排成你要的顺序**，并把你不想看到的项**收起来**。

> 许可证：MIT。

## 解决什么问题

这列菜单的顺序写死在每个插件自己的 `settings.section` 注册里（一个 `order` 数字），GUI 里既没有重排入口，也没有把不用的项收起来的办法。想把自己常用的项挪到上面、或把一年也用不到一次的项藏掉，只能去改别人的插件包——而应用内包在 asar 里（升级即丢），profile 下的包也会被插件更新覆盖。

本插件不碰任何第三方代码：排序靠给导航按钮打 CSS `order`，隐藏靠打 `display:none`。

## 怎么用

1. 打开「设置」，在左侧菜单里点最下面的「设置导航顺序」。
2. **排序**：按住每行左边的 `⋮⋮` 把手拖动；想精细调整也可以点 `↑` / `↓`。
3. **隐藏**：在不想看到的项上点「隐藏」——它就从左侧菜单里消失了，插件本身照常工作。
4. 点「保存」。左侧菜单立刻变样。

- 已经隐藏的行在面板里显示成灰色带删除线，点「显示」即可找回。
- 关掉「启用手动排序与隐藏」并保存 = 完全用各插件自己的样子。
- 点「恢复默认」= 清掉保存的顺序与隐藏，同样回到原样。
- 「设置导航顺序」这一页**不能隐藏自己**：它是唯一能取消隐藏的入口，藏了就再也进不来了。

## 原理

- 导航容器是 flex column，所以给子元素打 `style.order` 就能改变**视觉顺序**，而 DOM 顺序、各插件的代码、React 的 key 全都不用动。
- 隐藏只是给按钮打 `display:none`：**节点不删**，所以取消隐藏立刻回来，插件本身也不受影响。
- 拖拽用 Pointer Events 自己实现（`setPointerCapture` + 各行中线算落点），不引第三方库，也不只认鼠标——触摸屏同样能拖。落点由纯函数算：`dropIndex`（指针 Y → 插入位置）加 `adjustDrop`（把「含被拖项」的坐标换算成取出后的下标）；箭头与拖拽最终都走同一个 `moveTo`，两种操作的结果必然一致。
- 菜单项没有 id 也没有 data 属性，只能靠标签文本识别；同名项用「同名第几个」区分（配置里存 `{ name, index }` 而不是裸名字），所以菜单增删之后，旧配置不会把别的项挤错位。
- 设置面板由 portal 挂在 `document.body` 上，插件用 `MutationObserver` 观察 body 子树，面板一出现就重排；回调按帧合并，聊天区流式输出不会把它变成性能负担。

### 识别方式为什么是子串匹配

真实 DOM 里的类名是 CSS Modules 的哈希名（`ZiQlkq_navList` / `ZiQlkq_navLabel`），精确的 `.navList` 选择器**匹配不到**，所以本插件按 `[class*="navList"]` / `[class*="navLabel"]` 匹配：类名里含原名即可，DSH 换哈希前缀也不受影响。

## 数据存在哪

| 项 | 值 |
| --- | --- |
| 存储位置 | 浏览器 `localStorage`（不是宿主配置文件） |
| 键 | `dsh-settings-nav-order/v1` |
| 内容 | `{"enabled":true,"order":[{"name":"模型","index":0}, …],"hidden":[{"name":"Web 插件","index":0}, …]}` |

为什么不用配置文件：这是「这台机器上这个浏览器」的显示偏好，跨设备同步没有意义；也因此宿主半边是空实现，不需要 API、不需要读盘。

### 已知限制

- 顺序与隐藏都跟着浏览器 profile 走：换浏览器、换机器、清站点数据都会回到默认样子。
- 配置里已经不存在的菜单项（插件被卸载）当成陈旧项忽略，不影响其余项。
- 新装插件新增的菜单项，会排在已保存顺序的后面，默认也不会被隐藏。
- **界面语言会影响识别**：菜单项是靠显示出来的文字认的，切到英文界面后，「Web 插件」在配置里记的仍是中文名，那一项的顺序与隐藏会暂时不匹配（其余项不受影响）。切回中文即恢复。
- 隐藏只收入口、不卸载插件：被隐藏的插件功能照常工作；要彻底停用它请去插件管理页。

## 失败姿势

任何一步出错都退回「原样显示」：面板读不到、样式打不上、配置坏掉（坏 JSON、字段类型不对、隐私模式下 `localStorage` 抛异常），结果都只是顺序/隐藏没生效——不会白屏，也不会少项。

## 安装

通常随聚合包 `@fish-under-sea/dsh-fish` 一起装（见仓库根 README）。单独装：

```sh
dsh plugin --profile desktop add link:<本目录的绝对路径>
```

装完必须**重启 DSH**：`cordis.patch.yml` 的插件行只在启动时展开，刷新页面不够。

## 测试

```sh
node test/client.test.mjs
```

零依赖：用手写的假 DOM + 假 React 跑完整条链路（装载 → 计算顺序 → 落到元素上 → 设置页渲染与交互），共 36 个用例。

拖拽的指针跟手效果假 DOM 测不了（假元素没有布局），测试覆盖的是它依赖的纯函数（`moveTo` / `dropIndex` / `adjustDrop`）以及与箭头的结果一致性；手感请以实机为准。

> 不要用 `node --test test/`：测试运行器会派生子进程并捕获管道输出，在受限沙箱里会以 `EPERM` 失败。直接运行测试文件即可。

## 目录结构

| 路径 | 作用 |
| --- | --- |
| `lib/index.js` | 宿主半区，空实现（纯浏览器插件） |
| `lib/client.js` | 浏览器半区：顺序计算、隐藏与 `order`/`display` 应用、拖拽纯函数、设置页组件、插槽注册 |
| `cordis.patch.yml` | bundle 补丁层，把插件行插入 profile 名册 |
| `test/client.test.mjs` | 零依赖测试 |
