## 0.10.4 (2026-10-18)

- **Team plugin 0.7.2 → 0.7.3**: the new host's `spawn` subagent provider declares only `agentPreset` (no persona / toolFilter capability), while the old plugin still delivered member personas through `startActivation` — so every member failed with `agent-teams: provider "spawn" cannot apply a member persona`: teams could be created but no member could start. 0.7.3 installs the persona section and tool filter from the plugin's own activation hook on such preset-only hosts.
- **No more corrupted child sessions**: the old plugin wrote the composition snapshot as an `agent-teams/member-composition` session event; host 2.0.19 does not know that type and it was not marked ignorable, so reading the child session threw `SessionFormatUnsupportedError: … refusing to interpret the log` and prompt delivery reported `subagent "…" is unavailable`. 0.7.3 uses the host's plugin-record channel (`appendPluginRecord`, automatically `ignorable: true`) and rebuilds compositions from `team.json` on cold resume.
- **Compatibility matrix accepts `0.2.1-rc.2`** (the `dshVersion` bundled with DSH NEXT 2.0.19); all 21 `@deepseek-ai/dsh-*` peer ranges were widened accordingly.
- **`dsh-our-free-model-fish` removed from the bundle**: member count 14 → 13. Its 13 channel providers and channel gateway are heavy opt-in configuration; bundling it forced that load on people who only ever use one model, and it releases faster than the bundle. Install it separately with `dsh plugin --profile <profile> add dsh-our-free-model-fish`; the entry id (`our-free-model`) and data directory (`$DSH_HOME/our-free-model/`) stay the same, so **existing channel settings, check-ins and ledgers are untouched**.
- **No other dependency moved**: the 11 sub-packages and `dsh-better-reasoning-effort-fish@0.5.8` are all already the latest on npm, so this release has no other updates to match.
- Both READMEs updated (version block, plugin table, install examples, configuration, repository layout, footer), plus the `cordis.patch.yml` header counts and the `lib/index.js` comment; the stale "Development" command for the removed `dsh-client-ui-model-capabilities` sub-package is gone too.
- Full notes: [v0.7.3](https://github.com/Fish-under-sea/dsh-agent-teams-fish/releases/tag/v0.7.3).

> **🆕 0.10.1 (2026-10-16):** **`dsh-agent-teams-fish` 0.7.0 → 0.7.1 — fixes "a blank optional field makes team creation impossible".**
>
> - **Symptom**: a captain model that materializes every optional parameter as `""` instead of omitting it could never call `agent_teams_create`: it failed with `profiles.inline-plan.members[0].tool_policy must not be empty`, and switching to the literal `"default"` failed with `unknown tool policy "default" (no toolPolicies are configured in this deployment)`. The model then retried between the two errors (one real session: 34 consecutive failures, 0 successes, before it gave up and called it its own mistake) — **no member ever spawned**.
> - **Root cause**: the `add_member` / `edit_plan` path runs blank strings through `trimmedOptional()`, which normalizes them to `undefined` (accepted), while the inline-plan path uses `optionalNonEmptyString()`, which rejects any blank string — **the two paths disagreed**. The defect lives in `src/profiles.ts` and still exists unfixed in upstream v0.1.23.
> - **Fix**: `optionalNonEmptyString` now returns `undefined` for blank/whitespace-only values, matching the edit path. Required fields (`name`, task `id` / `subject`, `fallback.provider|model`, dependency ids) stay strict, and non-string values remain hard errors. Adds `scripts/inline-plan-blank-optional-tdd.mjs` (23 assertions), wired into `pnpm verify`.
> - **Also fixes two pre-existing `pnpm verify` failures**: `MTIME_TOLERANCE_MS` goes from 1 to 4 (`mtime` and `Date.now()` come from two different clocks; on Windows the filesystem clock runs up to 2.2 ms ahead, so a 1 ms tolerance misread files written *before* a verdict as modified *after* it — the precondition failed about 57.75% of the time); and a new `scripts/symlink-support.mjs` probes symlink permission uniformly so Windows without Developer Mode skips with a stated reason instead of failing outright.
> - **Verification**: full `pnpm verify` chain exits 0; `pnpm build` and `pnpm typecheck` pass; the README version gate passes.
> - **Alignment**: this release only widens the bundle dependency range (`dsh-agent-teams-fish: ^0.7.0 → ^0.7.1`); the bundle itself has no code change.

> **🆕 0.9.0 (2026-10-13):** **`dsh-video-preview` (forked) merged in; member count 14 → 15.**
>
> - **1 new upstream fork**: [zemul/dsh-video-preview](https://github.com/zemul/dsh-video-preview) (MIT) is forked into this repository under `packages/dsh-video-preview` and published independently as `@fish-under-sea/dsh-video-preview@0.1.5` — inline video preview in the sidebar (`.mp4` / `.webm` / `.mov` / `.mkv` / `.avi` and more), with its own `/video` route streaming HTTP Range responses so **seeking works**.
> - **Why fork**: same reason as the six existing forks — the package name is baked into the client bundle's module registration id (`dsh-client-modules` claims a factory by `package.json`'s `name`), so renaming is what makes independent releases possible and lets the fork coexist with the upstream package in one process.
> - **⚠️ It also fixes "installs but never activates" (important)**: upstream's host half declares `inject: ['webServer', 'sessions', 'webRuntime']`, but **the `webRuntime` service has been removed from the kernel** (DSH 0.2.1-alpha.2: the `dsh-web-app` web-runtime row no longer provides it; `client-connection` reads its trusted authorities from `webStartup` instead). A missing service in a cordis `inject` list means the row stays **PENDING FOREVER**, so on the new kernel upstream's `apply` never runs: the `/video` route is never registered, video requests fall through to the SPA static handler, and non-GET/HEAD requests get an **empty 405** (the UI shows a bare `HTTP 405`). This fork drops `webRuntime` from `inject` and resolves the trust list **lazily, per request** (`webRuntime` → `connection` → empty array); an empty array means **loopback-only**, so the change can only narrow, **never widen**, the trust boundary. It also removes the long-removed `@deepseek-ai/dsh-client-runtime` from `dsh.client.inject` (keeping it breaks the whole client bundle load).
> - **One compat shim dependency removed**: this machine previously kept upstream alive with the profile-level `dsh-webruntime-shim.mjs` (which also serves `dsh-better-sidebar`). The video-preview half **no longer needs it**; keep the shim if `dsh-better-sidebar` still requires it.
> - **Range semantics and guards untouched**: 200 / 206 / suffix ranges / 416 / HEAD / cross-site 403 / path-escape 403 all behave exactly as upstream, now covered by 28 route regression checks plus 8 identity-contract checks (`packages/dsh-video-preview/test/`).

> **0.8.2 / 0.8.3 (2026-10-12):** **`dsh-usage` 0.4.7 → 0.4.9 — the scenario line now counts DeepSeek consumption on every API, and its explanatory sub-line is gone.**
>
> **Background**: the line introduced in 0.4.7 counted only the **official family routes** (`deepseek-official` / `deepseek-account`). The user pointed out that is wrong — it should be "the DeepSeek consumption across every API currently retained". This machine's ledger shows how large that gap was: a single channel, `bailian`, carries **2.74 billion DeepSeek tokens**, against 260 million on the official account.
>
> **New scope**: a new core predicate `countsAsDeepSeekUsage(provider, model)` counts a row when its route is in the official family **or** its model id contains `deepseek` (case-insensitive); non-DeepSeek models (MiMo / Qwen / GLM / GPT / Claude …) stay excluded. Relay and aggregator traffic counts — a DeepSeek model served by an aggregator or free channel is still DeepSeek consumption.
>
> **Why the aggregation moved host-side (important)**: the wire caps each provider's model list at `SUMMARY_MODEL_CAP = 12`, so a browser-side sum would silently undercount once an aggregator serves more models than the cap. A dedicated test builds a 20-model scenario proving it: none of the 12 model rows the client receives is the DeepSeek one, while the host aggregate stays complete. `UsageWindowSummary.deepseek` and `UsageDayView.deepseek` were added, accumulated by `summarizeDays` in the same pass (it already holds the uncapped per-model maps, so there is no extra cost). The client's `officialPricingScenarios` only reads that bucket; **an older host gets one fewer line** rather than a figure that only ever saw the official account.
>
> **How the numbers move** (this machine's real ledger, 2026-09-11 → 2026-10-12): ¥22.06 / ¥11.03 → **¥1478.77 / ¥739.39** (4.93 billion DeepSeek tokens, 57.9% of all traffic). **The old figure reproduces the user's screenshot to the cent**, which is what makes the new one trustworthy.
>
> **UI**: as requested, the explanatory sub-line under the scenario line (`usage.bank.scenario.hint`) is removed from both dictionaries and from the render.
>
> **Verification**: 6 new tests pass (cross-route aggregation, official-alias fallback, non-DeepSeek exclusion, model cap not affecting the aggregate, real naming variants, older-host degradation, zero is not `undefined`, historical `cost` never reused); `tsc -b` and `tsdown` pass; the artifact contains the line and no longer contains the deleted copy.

> **0.8.0 (2026-10-12):** **6 upstream family plugins (forked) + 1 in-house plugin merged in; member count 7 → 14.**
>
> **① Six upstream forks (Apache-2.0)**: `dsh-task-board`, `dsh-git-graph`, `dsh-model-capabilities`, `dsh-ssh`, `dsh-usage` and `dsh-session-archive` from [zhu1090093659/dsh-web](https://github.com/zhu1090093659/dsh-web) (all at baseline `0.4.6`) are forked into `packages/`, published as `@fish-under-sea/dsh-client-ui-task-board` / `-git-graph` / `-model-capabilities`, `@fish-under-sea/dsh-ssh` / `dsh-usage` / `dsh-session-archive`.
>
> **Why forking was required rather than adding a dependency**: upstream bakes both the npm scope and the package name into the client bundle's **module registration id** (`window.__ModuleLoader__.load({ id: "@linxin666/…" })`), while the host's `@deepseek-ai/dsh-client-modules` claims a package by its **`package.json` `name`** in `nearestPackage()` (accepting it only when `name === expectedPackageName`). When the two disagree the claim fails and the **entire browser half (settings page, panels) does not load**. Renaming therefore requires editing sources and rebuilding the bundle — which is also the prerequisite for independent releases and for tracking the kernel going forward.
>
> **② What changed (scope and telemetry only; behaviour equivalent to upstream 0.4.6)**:
> - Package names and npm scope: `@linxin666/*` → `@fish-under-sea/*`, with every reference in sources, configs and docs updated too — including the **process-wide mount guard identifier** in `mountOnce("<package name>")`, without which the fork and the upstream original would be treated as the same plugin and crowd each other out.
> - **Install telemetry removed**: upstream's `shared/client/telemetry.ts` reports the package name to `https://dsh-market.com/api/telemetry/event` once a day. Affects `dsh-task-board`, `dsh-git-graph` and `dsh-ssh` (their `src/client/telemetry.ts` plus its import and call are gone). The other three packages never had telemetry.
> - **Two upstream defects fixed**: `dsh-session-archive` declared the unscoped `schemastery` in `dependencies` while its sources import the scoped `@deepseek-ai/schemastery` (a TS2307 type-resolution failure at build time) — now `^3.18.4`; and the upstream typo `dsh-client-ssh` in the `@module` JSDoc of `dsh-ssh`'s `native-panel.tsx` is corrected.
> - Each package carries a **`NOTICE`** (required by Apache-2.0 §4b): source repository, source package name and version, modifications, licence and disclaimer.
> - **`tests/` are not carried over** (the six upstream packages hold 230 test files, ~39% of their file count): this repository maintains `src/` + `lib/` only, rebuilding with `pnpm --filter <package> build` after source changes.
>
> **③ Build chain**: the upstream repository-root shared build preset is ported into this repository's `shared/` (`tsdown.client.ts`, `web-platform.ts`, `types/css-modules.d.ts`), and the root `package.json` gains build devDependencies (`tsdown@0.22.2`, `typescript@~5.7.2`, `lightningcss@^1.32.0`). **Note**: `lightningcss` must be installed at the **repository root**, because the shared preset resolves its dependencies from there. `lib/` is committed, so the release flow still needs no build step.
>

Enabling both mounts them **twice** (two task boards fighting over one sidebar seat, the same host services registered twice). This bundle deliberately **does not rewrite other packages' entries** (cross-package interference creates coupling and `entry not found` warnings).

> **0.7.9 (2026-10-12):** `dsh-agent-teams-fish` **0.6.0 → 0.6.1** (dependency range `^0.6.0` → **`^0.6.1`**) — **fixes "the plugin gets its whole row disabled after upgrading DSH to 0.2.1-alpha.2"**.
>
> **Symptom**: after the DSH runtime moved to `0.2.1-alpha.2`, the host log showed `disabling profile plugin row "agent-teams": Plugin dsh-agent-teams-fish@0.6.0 is incompatible with dsh 0.2.1-alpha.2`, the plugin showed as broken in the panel, and **AgentTeams collaboration did nothing at all**. This is not a crash but DSH's deliberate protection: when the declaration surface has not followed the runtime, it would rather disable the plugin than risk a crash or data loss.
>
> **Root cause**: that repository treats `compatibility.json` as the **single source of truth** and makes `scripts/compatibility.mjs` enforce that "every peer range must exactly enumerate its host versions". The runtime moved on and that enumeration did not — **the plugin code itself is not defective** (its compiled output value-imports only `@deepseek-ai/dsh-llm` and `@deepseek-ai/schemastery`, both of which still export on the new host; every other `@deepseek-ai/*` import is a type-only import erased at compile time).
>
> **Fix**: add `0.2.1-alpha.2` to `supportedHosts` with `track: preview`, then append it to all **21** `@deepseek-ai/dsh-*` peer ranges (the gate forces this step: change only the source of truth and it immediately reports `peer range must enumerate the supported host targets`). `recommendedHost` **stays** on the stable `0.2.0-rc.2` — an alpha must not be the ordinary-user recommendation. **No wide range**: DSH compares with `includePrerelease`, so `>=0.2.0-rc.2` would claim compatibility with every future version, contradicting that repository's stance of declaring a host only after testing it.
>
